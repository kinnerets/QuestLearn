# מסמך אפיון מוצר מלא – QuestLearn (גרסה 3)

> **סטטוס:** אפליקציה אישית לשתי בנות — מילי (כיתה ג') ואחותה (כיתה ה').
> **גרסה זו (v3)** ממקדת את המוצר סביב עצמאות הילדה וחיכוך הורי אפס: ביטול סנכרון מול קצב בית הספר, הידוק כלכלת מטבעות נגד "שיחוק" (gaming), Onboarding חווייתי במקום מבחן דיאגנוסטי, מימוש פרסים אוטומטי מבוסס שובר דיגיטלי, וכיוונון מנוע ה-STT לערבית מדוברת בקול ילדים. ראו נספח "שינויי v3".

## 0. החלטות מוצר מנחות (Product Decisions)

|------|--------|-------------------|

| ערבית | מדוברת (מדוברת פלסטינית/לבנטינית) בכיתה ג', ספרותית (פֻצְחַא) בכיתה ה' | שני מסלולי תוכן + שני מנועי STT/הגייה נפרדים |

| טון תנ"ך | תרבותי-סיפורי + מותאם לביה"ס | סיפורי מורשת, ערכים ודמויות, בהתאמה למה שנלמד בכיתה |

## 1. ארכיטקטורה טכנולוגית (Technical Specification)

### א. תרשים זרימת מערכת (System Flow) — מעודכן

│  (Next.js / PWA) │      │   GraphQL / REST API    │      │ Users, Mastery, Events │
│  IndexedDB (off) │      │                         │      └───────────────────────┘
└──────────────────┘      │  ┌───────────────────┐  │

┌──────────────────┐      │  │ Composer (מנוע     │◄─┼─────►│ Content & Vector Store │
│   ממשק הורים     │◄────►│  │ המלצות חכם)        │  │      │ (Curriculum + Q-Bank)  │

                          │  └───────────────────┘  │      └───────────────────────┘

                          └────────────────────────┘

**מה חדש לעומת גרסה 1:**
- **Daily Quest Composer** — מנוע המלצות שמרכיב את המשימה היומית (סעיף 4).
- **Content Pipeline דו-שלבי** — Generate → Verify → Store, עם דגלים להורה (סעיף 1ג).
- **IndexedDB / Offline queue** — הורדה מראש וסנכרון.
- **Mascot כרכיב-על** — משתמש ב-LLM עם context של הילדה.

### ג. אינטגרציות ו-AI Content Pipeline

**1. הפקת תוכן (Generate):** LLM עם JSON Schema Output מייצר שאלות לפי נושא ומאגר הידע של משרד החינוך. כל שאלה כוללת: גוף השאלה, תשובות, **רמזים מדורגים** (רמז 1 → רמז 2 → פתרון מודרך), הסבר פדגוגי, ו**מיפוי כל מסיח שגוי לסוג טעות** (misconception).

**2. אימות אוטומטי (Verify):** מודל שני (Verifier) בודק כל שאלה שנוצרה — נכונות התשובה, התאמה לגיל, רגישות, ואיכות הניסוח. תוצאה:
- `auto_passed` → נכנס ישר למאגר.
- `auto_flagged` → נכנס למאגר וזמין מיד; מסומן בדגל **אינפורמטיבי** בדשבורד ההורה ("נבדק אוטומטית"). **v3:** הדגל הוא דיווח בלבד — אין תור אישור, אין חסימה, ואין פעולה נדרשת מההורה.

**3. STT דו-מסלולי:**
- **מדוברת (כיתה ג') — כיוונון v3:** זיהוי **גמיש וסלחני** (Phonetic Tolerance / Fuzzy Matching) המותאם לניב לבנטיני ולקול/טונאציה של ילדים (Child Pitch). **מנגנון Fallback:** אם הזיהוי אינו בטוח — הילדה מקבלת עידוד חיובי על עצם הניסיון וההקלטה, **ללא ציון פוסל** ("שמעתי אותך יופי! בואי ננסה עוד פעם ביחד").
- **פֻצְחַא (כיתה ה'):** Whisper/Speech API עם דיוק גבוה יותר לאלפבית ולמילים תקניות.
- הקלטות נמחקות אוטומטית לאחר ניתוח (`delete_after`).

**4. TTS (קול קפי):** מנוע Text-to-Speech בעברית לקול המנחה — הקראת הוראות, רמזים, עידוד וחגיגה. חשוב במיוחד לבת ג' ולקורא מתקשה (נגישות). קול חם וידידותי התואם לאישיות קפי.

**5. Notifications Engine (ממוקד):**
- **בת ה' (עם טלפון):** תזכורות streak ישירות אליה + סיכום להורה, בשעות אחה"צ/ערב בלבד.
- **בת ג':** ללא התראות ישירות; ההורה מקבל תזכורת/סיכום.
- **כלל:** שקט בשעות בית ספר; חלון התראות מוגדר על ידי ההורה.

## 2. חוויית משתמש ועיצוב ממשק (UX/UI Specification)

### א. עקרונות עיצוב
- **שפה:** Clean Gamified Minimalist — פסטל נעים, קווים עגולים, אלמנטים רכים.
- **טיפוגרפיה:** גופן עברי קריא (Rubik / Assistant), ניקוד לפי צורך (חשוב יותר לבת ג').
- **מיקרו-אינטראקציות:** אנימציית סיום, Haptic קל, ארנק מטבעות ויזואלי.
- **רספונסיביות מלאה:** אותה חוויה בטלפון, טאבלט ומחשב (החלטת מכשירים).
- **נגישות:** מתג ניקוד, הגדלת פונט, הקראת טקסט (TTS) לקורא מתקשה, מצב ניגודיות.

### ב. הדמות המנחה — "קפי" (Capi) — חדש
קפיברה אינטליגנטית, רגועה ואופנתית באנרגיית **"Chill & Smart"**. המדריך המלא: [`docs/character-capi.md`](./character-capi.md).
- **מברכת בשם**, זוכרת הישגים אחרונים ("אתמול כבשת את לוח הכפל!").
- **נותנת רמזים מדורגים** בזירת התרגול במקום תשובה בינארית.
- **מגיבה בזמן אמת** (מבוסס-LLM עם context של הילדה: נושא, מצב שליטה, טעויות).
- **לא נלחצת מטעות:** הבעה נינוחה ומעודדת ("הכל טוב, בואי נסתכל על זה שוב יחד").
- **גשר גילאים:** לבוש אורבני (ג'קט ורסיטי + אוזניות) קוּלי לכיתה ה', חמוד ונגיש לכיתה ג'.
- **גבולות בטיחות:** אין צ'אט חופשי פתוח לילדה — קפי פועלת בתבניות מונחות (רמזים, עידוד, הסבר), עם סינון תוכן. זה שומר על בטיחות למרות "אמון מלא ב-AI".

### ג. מסכי הילדות

**מסך 0 — Onboarding חווייתי (v3, במקום מבחן דיאגנוסטי)**
כניסה ראשונה קצרה, צבעונית וכיפית — ללא תחושת מבחן:
1. **היכרות עם קפי** + בחירת/עיצוב אווטאר.
2. **בחירת תחומי עניין** (אופנה, יזמות, חיות, AI, ...) → מזין את `interests`.
3. **סיור מהיר בחנות הפרסים** — הצגת האפשרות לזכות בפרסים אמיתיים (מוטיבציה מיידית).
4. **3 שאלות חימום** קלילות ואינטואיטיביות → **כיוונון רמת קושי ראשונית סמוי** (mastery התחלתי), בלי שהילדה מרגישה שנבחנת.

**מסך 1 — הבית והמסלול היומי (Daily Quest Path)**
- Header: אווטאר, מטבעות, מד רצף.
- 3 תחנות: (1) עוגן חובה (חשבון/שפה), (2) שפות (ערבית/אנגלית), (3) שער העתיד (העשרה).
- **התחנות נבחרות ע"י המנוע החכם** (סעיף 4), לא קבועות מראש.
- נעילה דינמית: העשרה נפתחת אחרי החובה. האווטאר מתקדם פיזית על המפה.

**מסך 2 — זירת התרגול (Exercise Canvas)**
- שאלה אחת בכל פעם, ללא הסחות.
- רכיבים: כפתורים גדולים, גרירה, מיקרופון עם גלי קול מונפשים.
- **משוב:** נכון → צליל + נקודות. שגוי → **רמז מדורג** מהמנחה (לא "נכשלת"), ומיפוי הטעות למערכת.
- ללא מנגנון "לבבות"/עונש — מצב אימון ללא לחץ.

**מסך 3 — "המצב שלי" (Child Dashboard)**
- רדאר ידע / עץ מיומנויות.
- "חוזקות בולטות" (3 מובילות) לביטחון עצמי.
- "תחומים לאימון" → כפתור "אימון ממוקד 2 דק'".

**מסך 4 — חנות התגמולים המשפחתית**
- קלפי פרסים **מגוונים** (זמן מסך, חוויה, זכות, פעילות משפחתית) עם בר התקדמות ("עוד 30 מטבעות ל...").
- **מימוש אוטומטי (v3):** בהגעה ליעד ולחיצה על "מימוש" → המטבעות מנוכים מיד ונוצר **שובר דיגיטלי / קבלה** במסך (`voucher_code`).
- הילדה **מציגה פיזית להורה** את השובר באפליקציה. אין כפתור אישור, אין המתנה.

### ד. דשבורד הורים (v3 — צפייה, לא שערים)
- בחירת ילדה + **תמונת מצב שבועית** (זמן, רצף, יחס ליבה/העשרה).
- **אבחון פדגוגי**: לא רק "דיוק 55%", אלא **שורש הבעיה** (איזו טעות חוזרת) + המלצת פעולה בלחיצה.
- **מרכז התערבות ידנית (אופציונלי):** Pin / Boost / Lock / Inject (סעיף 4).
- **שוברי פרסים:** תצוגת סטטוס זכאות ומימושים אחרונים (`issued`) — **לצפייה בלבד**, ללא אישור/דחייה. סימון "קיבלה" אופציונלי.
- **דגלי תוכן:** רשימת `auto_flagged` **אינפורמטיבית** — לצפייה, ללא פעולה נדרשת.
- **ניהול כלכלת פרסים:** קביעת עלויות והוספת פרסים משפחתיים מותאמים אישית.

## 4. המנוע החכם + התערבות ידנית (Smart Engine)

### א. Daily Quest Composer — ציון משוקלל
לכל נושא רלוונטי מחושב ציון עדיפות; שלוש התחנות היומיות נבחרות מהמובילים:

```
priority = 0.40 × mastery_gap        (1 − mastery_score)
         + 0.25 × review_urgency     (כמה next_review_at עבר/קרוב)
         + 0.15 × skill_readiness     (prerequisites הושלמו → מוכן; רצף מיומנויות, לא רצף פרקי הכיתה)
         + 0.10 × interest_match     (interests של הילדה)
         + 0.10 × freshness          (הימנעות מחזרה על אותו נושא ברצף)
         × parent_directive_modifier (Pin/Boost/Lock מכפילים/מאפסים)
```
> **v3 — ללא סנכרון סילבוס:** `skill_readiness` נשען על תלויות מיומנות (prerequisites) בתוך התוכנית השנתית, **לא** על מעקב אחר הפרק שהמורה מלמדת כרגע. הקצב אישי ועצמאי לחלוטין.

### ב. פדגוגיה מתחת למכסה
- **חזרה מרווחת (SM-2 מפושט):** תשובה נכונה מרחיקה את `next_review_at` (interval × ease_factor); טעות מאפסת. מבטיח שמילי לא תשכח את לוח הכפל.
- **טקסונומיית טעויות:** כל מסיח שגוי ממופה לסוג טעות → רמדיאציה ממוקדת + הסבר שורש להורה.
- **סולם רמזים:** רמז 1 → רמז 2 → פתרון מודרך, דרך המנחה.
- **כיוונון סמוי מ-Onboarding (v3):** במקום מבחן מיקום — 3 שאלות החימום מה-Onboarding נותנות `mastery_score` התחלתי; המערכת ממשיכה לכייל תוך כדי משחק (אין מסך "מבחן").
- **התאמת קושי דינמית:** 3 נכונות ברצף → מעלה `difficulty`; טעויות → מוריד.

### ג. שכבת התערבות ידנית (Parent Override)
| פעולה | מה עושה |
|-------|---------|
| **Pin** | "השבוע דגש על שברים" → מעלה משקל אוטומטית |
| **Lock / Unlock** | נעילה/פתיחה ידנית ואופציונלית של נושא (v3: הכל פתוח כברירת מחדל) |
| **Inject** | הזרקת נושא נקודתי ("מחר מבחן על תיבת נח") |
| **Boost interest** | הטיית ההעשרה לכיוון שהילדה אוהבת |

### ד. רדאר תוכן פרואקטיבי
המערכת יוזמת המלצות להורה: "זוהתה חולשה בחיסור במאות → להזריק מיני-אתגר?" בלחיצה אחת.

## 5. משחוק ותגמולים (Gamification & Retention)

- **Daily Streak Engine:** יום שהושלמו 3 השלבים → רצף +1. "הקפאת רצף" נרכשת במטבעות.
- **כלכלת מטבעות נגד שיחוק (v3):**
  - **תקרת מטבעות יומית (Daily Coin Cap):** עיקר ה-Quest Coins מתקבל **אך ורק** מהשלמת 3 תחנות המסלול היומי. מעבר לתקרה — אין צבירת מטבעות נוספת באותו יום (`Daily_Progress.coins_awarded_today`).
  - **תשואה פוחתת (Diminishing Returns):** תרגול חוזר של נושא **שכבר נשלט** מזכה ב-XP לאווטאר בלבד — **לא** במטבעות לחנות. כך שומרים על ערך הפרסים ומעודדים התקדמות אמיתית ולא "פארם".
- **תגי הישג:** מומחית לוח הכפל (>90%), מעצבת צעירה, שגרירה קטנה (10 שיחות ערבית) ועוד.
- **פרסים מגוונים (החלטת תגמול) — 4 קטגוריות:** (1) זמן מסך מבוקר, (2) פעילות משפחתית (משחק קופסה, גלידה, ערב סרטים), (3) זכויות והרשאות (בחירת ארוחה, ער מאוחר, מוזיקה באוטו), (4) פרסים פיזיים קטנים (מדבקות, ערכת יצירה, ספר). מפחית תלות בתגמול מסכי בלבד.
- **Co-Op בין אחיות — לא תחרותי:** שתיהן סיימו באותו יום → בונוס משותף +25%. **אין דירוג ביניהן.** בנוסף: "מטרה משפחתית שבועית" משותפת (Family_Goals).

## נספח ב — שינויי גרסה 3 (v3)
1. **ללא סנכרון סילבוס:** הוסרו מנגנוני מעקב פרקים מול הכיתה; חיזוק רוחבי בקצב אישי (`skill_readiness` במקום `curriculum_flow`).
2. **כלכלת מטבעות אנטי-שיחוק:** תקרת מטבעות יומית (`Daily_Progress`) + תשואה פוחתת (נשלט → XP בלבד).
3. **Onboarding חווייתי** במקום מבחן דיאגנוסטי (מסך 0), עם כיוונון קושי סמוי.
4. **חיכוך הורי אפס:** בוטלו כל מנגנוני ה-Pending/Approval; מימוש פרסים אוטומטי מבוסס שובר (`Reward_Redemptions`); דגלי תוכן אינפורמטיביים בלבד; נושאים רגישים פתוחים כברירת מחדל.
5. **STT ערבית מדוברת (ג'):** זיהוי גמיש/סלחני מותאם לקול ילדים + Fallback מעודד ללא ציון פוסל.
6. שינויי סכמה: הוסרו סטטוסי אישור מ-`Questions_Bank` ו-`Reward_Store`; נוספו `Reward_Redemptions` ו-`Daily_Progress`; `parent_lock_default` → `is_sensitive`.
